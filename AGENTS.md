# VERA Repository Guide

## Project scope

VERA is a local-first research workspace. The orx Rust CLI owns local projects, the dashboard API, the SQLite store, coding-agent integrations, experiment orchestration, and execution backends. The React dashboard lives in ui/.

Do not add product-account, organization, managed VERA compute, or upstream feedback integrations. Keep academic-source clients and locally configured execution backends available. Preserve dormant environment and database-access settings for future adaptation.

## Compatibility and data

Existing users may have configuration, environment values, databases, or SSH settings under historical OpenResearch-named paths. Those paths remain compatibility locations. Do not rename, delete, or migrate their contents as part of ordinary cleanup.

Research projects, runs, logs, and artifacts are local. Academic-source and compute-provider connections are separate user-configured capabilities.

## Development

- Rust code lives in src/; dashboard code lives in ui/src/.
- On Windows, use Jalankan-VERA-Localhost.cmd for an isolated local app instance; it builds the backend from source and stores development data under LocalAppData. Use scripts/dev-slot.mjs for isolated local app instances on macOS and Linux.
- ui/dist is committed and embedded in release builds. After UI changes, run pnpm build in ui/ and keep the generated bundle in sync.
- Prefer canonical Tailwind utilities such as flex flex-col h-full min-h-0 and project theme aliases such as bg-background, text-subtext, and border-border.
- Keep generated files generated by their existing tool; do not hand-edit Paraglide output.

## Audit and packaging

Follow .github/workflows/ci.yml for the complete CI check list. The normal Windows VERA package is built with windows/build-single-file.ps1. Validate a packaged candidate before replacing a working install.

Local build commands:

- Rust formatting: cargo fmt --all --check
- Rust tests: cargo test --locked
- Dashboard build and type check: pnpm build from ui/
- Dashboard unit tests: pnpm test from ui/
- Styles: pnpm lint:styles from ui/
